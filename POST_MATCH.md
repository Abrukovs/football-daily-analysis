# Post-match журнал и ROI

`football_analysis.py daily` добавляет каждый опубликованный вариант в `post_match_journal.csv` со статусом `PENDING`. Исходный предматчевый отчёт не изменяется.

После завершения матчей подготовьте JSON с фактическими голами:

```json
[
  {"fixture_id": "ID_FROM_JOURNAL", "home_goals": 2, "away_goals": 1}
]
```

Затем выполните:

```bash
python3 football_analysis.py settle --results results.json
```

Скрипт заполнит `WON`/`LOST`, прибыль в единицах ставки и выведет:

- число рассчитанных ставок;
- число выигрышей и проигрышей;
- суммарную прибыль в units;
- ROI = прибыль / сумма рассчитанных ставок × 100%.

Для ML ничья считается проигрышем, если выбран победитель матча. Для ТБ 2,5 нужен минимум 3 гола, для ТМ 3,5 — максимум 3, для ОЗ «Да» гол каждой команды, для ОЗ «Нет» — ноль голов хотя бы одной команды.

До публикации ROI нужно проверять фактические результаты по источникам и сохранять источник и время получения. Не смешивайте разные версии линии: в журнале сохраняется коэффициент, зафиксированный при генерации отчёта.

## Автоматическое обновление простого журнала

Файл `bets_journal.csv` обновляется GitHub Actions без ручного ввода. Ежедневная последовательность:

1. Запросить ESPN public scoreboard по дате и сопоставить завершённые матчи.
2. Для строк, которые ESPN не подтвердил, запросить TheSportsDB v1 `eventsday` через общий бесплатный ключ `123` (либо необязательный `THESPORTSDB_KEY`, если он задан).
3. Если остались строки и задан Secret `FOOTBALL_DATA_TOKEN`, использовать football-data.org как третий источник. Для его бесплатного тарифа нужен токен; покрытие ограничено бесплатными соревнованиями, а результаты могут быть задержаны.
4. Рассчитать `WON`/`LOST` только при завершённом статусе, известном счёте и однозначном совпадении хозяев и гостей. Иначе сохранить `PENDING`.

Для `bets_journal.csv` берётся фактическая дата начала матча в московском времени из отчёта, а не дата, когда отчёт был создан. Старые строки со статусом `PENDING` корректируются только при однозначном соответствии отчёту; уже рассчитанные записи не переписываются. Тоталы `ТБ/ТМ` принимают десятичные значения как с точкой, так и с запятой.

ESPN используется через публичный, но недокументированный JSON-интерфейс, поэтому его структура может измениться. TheSportsDB ограничивает бесплатный общий ключ 30 запросами в минуту и задаёт лимиты отдельно для разных endpoint. Не следует считать источники гарантией полноты: журнал намеренно оставляет сомнительные строки в ожидании.

Для предматчевой формы `football_analysis.py` сначала использует расписание ESPN; если завершённых игр меньше пяти, пробует найти прошлые матчи через `eventsday` TheSportsDB, проверяя до 60 дней с кешированием и ограничением частоты. `eventslast` не используется как надёжный источник формы, так как на бесплатном уровне он может возвращать только домашние матчи. При наличии токена football-data.org служит третьим резервом.

Штатный workflow также формирует новый отчёт через The Odds API. Его бесплатная квота — 500 кредитов в месяц; в текущей конфигурации восемь лиг × два рынка означают максимум 16 кредитов за запуск. Если ключ коэффициентов отсутствует или лимит исчерпан, генерация отчёта завершится ошибкой, но workflow всё равно попытается синхронизировать и сохранить уже рассчитанные статусы.
