# Daily Football Analysis

Ежедневные предматчевые отчёты по футболу. Отчёты создаются автоматическим заданием в 05:00 по московскому времени и сохраняются в формате Markdown.

## Что находится в репозитории

- `daily_football_report_YYYY-MM-DD.md` — ежедневный отчёт;
- `current_findings_YYYY-MM-DD.md` — рабочие заметки отдельных дней, если они нужны для аудита;
- `METHODOLOGY.md` — подробное объяснение отбора исходов и причин отказа от ставки;
- `IMPROVEMENT_IDEAS.md` — план автоматического деплоя и идеи повышения прозрачности анализа;
- `bets_journal.csv` — простой журнал опубликованных прогнозов: дата, матч, турнир, рынок и результат;
- `.gitignore` — список файлов, которые не следует отправлять в GitHub.

## Как скачать проект на другой сервер

1. Установите Git.
2. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/Abrukovs/football-daily-analysis.git
   cd football-daily-analysis
   ```

3. Откройте отчёты обычным редактором Markdown или текстовым редактором.

## Автоматическая отправка изменений

Скрипт `sync_to_github.sh` добавляет изменения, создаёт коммит и выполняет `git push origin main`:

```bash
./sync_to_github.sh
```

Ежедневное задание должно запускать этот скрипт после сохранения нового отчёта. Если вы меняете файлы вручную, запустите скрипт самостоятельно.

## Как вручную сохранить изменения

```bash
git add .
git commit -m "Обновить ежедневный отчёт"
git push
```

После настройки автоматизации ежедневный отчёт должен сохраняться и отправляться в GitHub автоматически. Перед использованием другого сервера проверьте расписание, часовой пояс `Europe/Moscow`, доступ к GitHub и источник коэффициентов.

## Важно о безопасности

В этот репозиторий нельзя добавлять токены, пароли, API-ключи, cookies браузера, файлы конфигурации Manus или приватные данные. Если на новом сервере нужны секреты, задавайте их через переменные окружения или защищённое хранилище секретов.

## Ограничения резервной копии

GitHub хранит копию файлов репозитория и истории изменений. Само расписание, подключённые аккаунты, браузерные сессии и секреты не переносятся этим репозиторием автоматически. Их нужно настроить отдельно на новом сервере.

## Автоматический генератор отчётов

`football_analysis.py` получает предстоящие матчи и коэффициенты через The Odds API. Недавняя форма берётся из ESPN; если доступно меньше пяти завершённых матчей, скрипт пробует TheSportsDB, а затем football-data.org при наличии бесплатного токена `FOOTBALL_DATA_TOKEN`. ESPN использует публичный недокументированный интерфейс и может измениться. Если история остаётся недостаточной, матч пропускается, а не оценивается по нулевым данным.

API-Football больше не требуется. Для генерации новых отчётов по-прежнему нужен `ODDS_API_KEY` от The Odds API. Его бесплатный тариф даёт 500 кредитов в месяц; текущий набор из восьми лиг и двух рынков расходует максимум 16 кредитов за ежедневный запуск (до 496 за 31-дневный месяц). РПЛ исключена, чтобы уложиться в эту квоту.

Для локального запуска задайте ключ коэффициентов:

```bash
export ODDS_API_KEY="..."
# Необязательно: бесплатный зарегистрированный токен football-data.org.
export FOOTBALL_DATA_TOKEN="..."
python3 football_analysis.py daily
```

GitHub Actions использует Secret `ODDS_API_KEY`; `FOOTBALL_DATA_TOKEN` — необязательный Secret для дополнительного источника. Для формы и результатов TheSportsDB используется как бесплатный резерв после ESPN; общий ключ `123` ограничен 30 запросами в минуту, а вызовы к дневному календарю кешируются и не идут чаще одного раза примерно за 2 секунды. football-data.org подключается последним при наличии токена. Нераспознанные или неоднозначные матчи остаются `PENDING`.

Repository Variable `ODDS_SPORT_KEYS` может выбрать подмножество, но код разрешает только фиксированные восемь лиг и игнорирует любые другие значения, поэтому переменная не может превысить расчётный лимит бесплатной квоты. РПЛ в allowlist отсутствует. Рынки задаются через `ODDS_MARKETS` и по умолчанию включают `h2h,totals`.

Workflow `.github/workflows/daily-analysis.yml` запускается в 02:00 UTC, то есть в 05:00 по Москве, и может запускаться вручную. Если генерация отчёта не сработает из-за отсутствующего ключа коэффициентов или исчерпания квоты, workflow всё равно попытается сохранить уже рассчитанные результаты, а затем завершится с ошибкой, чтобы проблема была видна в журнале запусков.

## Post-match журнал и ROI

Каждый выбранный вариант добавляется в `post_match_journal.csv` со статусом `PENDING`. После получения фактических результатов запустите:

```bash
python3 football_analysis.py settle --results results.json
```

Формат `results.json` и правила расчёта описаны в `POST_MATCH.md`. ROI считается по единичной фиксированной ставке: выигрыш даёт `odds - 1`, проигрыш — `-1`, а ROI равен суммарной прибыли, делённой на число рассчитанных ставок.

## Простой журнал результатов

Для быстрого просмотра используется файл `bets_journal.csv`. В нём намеренно оставлены только основные поля: `date`, `match`, `tournament`, `market` и `result`.

Новые прогнозы добавляются со статусом `PENDING`. Дата в журнале берётся из времени начала матча (`Начало`) в отчёте, а не из даты создания отчёта; для старых записей с однозначным соответствием дата исправляется перед расчётом, только пока строка остаётся `PENDING`. Перед генерацией нового отчёта GitHub Actions рассчитывает уже записанные `PENDING` через ESPN, затем TheSportsDB, а при настроенном `FOOTBALL_DATA_TOKEN` — через football-data.org; после генерации он синхронизирует новые прогнозы. Матч сопоставляется по московской дате и названиям хозяев/гостей; если источник не подтверждает завершение или совпадение неоднозначно, строка остаётся `PENDING`.

Скрипт `journal_sync.py` выполняет эту работу. Workflow запускается ежедневно в 02:00 UTC, то есть в 05:00 по Москве. Для ESPN и общего ключа TheSportsDB регистрация не нужна; для альтернативного football-data.org нужен отдельный бесплатный токен. Этот журнал отражает опубликованные прогнозы, а не факт совершения реальной ставки: ставки через проект не выполняются.
